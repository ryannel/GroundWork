# Explain systems through their value flows

First run `npm run --silent workspace -- list --json` in the Groundwork checkout. Resolve the workspace id and folder
from the registry, not `workspaces/`; see [workspace discovery](../README.md#find-the-workspace-first).

Help a first-time viewer follow information from creation and preparation to use and outcome. Interpret
purpose and reading order with the LLM; ground identities, ownership and exchanges in the recorded
model and cited source. Save the interpretation so page rendering is deterministic. The user's scope,
presentation preferences and existing authorisation govern the work; an audit-only request stays read-only.

## Choose the relevant workflow

- **Author or improve a chart:** use [representation](references/representation.md) for production fields,
  evidence and validation. Begin with the existing explanation and the business work, not a technical call graph.
- **New or changed scan evidence:** use [maintenance](references/maintenance.md) to reconcile the affected
  systems, neighbouring areas and saved choices without rewriting unaffected diagrams.
- **Whole dataset:** use [batch runs](references/batch.md) for the roster, bounded parallel work and review
  ledger. Account for every system; sampled visual success does not certify unseen charts.
- **Detached cards or groups:** use [orphan investigation](references/orphans.md). Review both relationships
  and membership; absence in a partial scan is not proof of an unused component.

Use [groundwork-landscape](../groundwork-landscape/SKILL.md) when area purposes or membership need revision,
and [groundwork-ask](../groundwork-ask/SKILL.md) for a focused evidence question. Load only the references the
current task needs. Evaluate substantial workflow changes with [held-out cases](references/evaluation.md).

## Modelling decisions that matter

- Explain the information, its creators, transformations, resting places and consumers. Keep background
  preparation, later requests and genuinely independent work distinct; parallel contributions need no
  invented sequence or decorative bridge through shared identity, flags or infrastructure.
- Put sources towards the left and consumers towards the right. Area-wide system columns and a system's
  internal component stages express different reading orders. Arrows retain their actual direction:
  push is sender → receiver, pull is requester → provider, events are producer → topic → consumer.
- Start with systems collapsed, once each, and a concise backbone of meaningful exchanges. Audit business
  collaborations as well as connectivity. Keep secondary work accessible through selection, expansion and
  **All connections**; simplicity is an editorial choice, not deleted evidence or a fixed edge quota.
- Labels describe action and information, including material conditions. Summarise the full rolled-up
  purpose faithfully; mixed reads and updates are not merely “Read”. Keep exact calls and evidence in detail.
- Check ownership and usage across the workspace. A single-service store or owned/published topic belongs
  inside its service card; event consumers remain dotted service exchanges. Shared or unknown-owner
  resources remain independent. Expanded service cards expose APIs, stores, topics and both directions of use.
- Keep support near its work inside a clear system boundary, with a subtle consistent tint and an accessible
  collapse control. Expansion restores reading size; explicit Fit map provides orientation for large canvases.
  Filtering and All connections retain card positions, and headings must stay with their local cards.

## Complete the requested result

Continue through supported local repairs, validation, rendered inspection and correction of review findings
within the authorised scope. Isolate an evidence gap and finish unaffected work rather than stopping a batch.
Keep facts separate from **Inferred** reading order, summaries and core/supporting choices. Retain stable IDs,
input revisions, rationale and uncertainty; a valid reference alone does not establish meaning or direction.

For changed charts, inspect the overview at reading size, expanded systems and representative service
cutaways. Compare default and All connections; check labels, ports, neighbouring boundaries, controls and
retained identities. Use independent review when warranted. Record what was actually seen, what was only
checked mechanically, and any remaining evidence or renderer limitation. Every apparent orphan needs a
supported disposition or precise unresolved question before the declared review scope is complete.
