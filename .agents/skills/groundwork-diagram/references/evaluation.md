# Behavioural evaluation

After substantial skill changes, give an independent agent the skill, a realistic request and raw evidence
in a disposable output folder. Withhold expected decisions below from that agent. Inspect its actual output,
not just its assurance that it followed instructions. Use held-out systems as well as Commercial regressions.

| Raw situation                                                                           | Observable decision to assess                                                                              |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Admin publishes changes; calculator requests cached data                                | Preparation and request paths remain distinct; arrows follow actual initiation, not column order.          |
| Bank returns a requested quote to a downstream consumer                                 | Bank sits towards the source side while request direction remains consumer → bank.                         |
| Store has one visible user but another user outside the area                            | Global usage prevents false private-resource folding.                                                      |
| Single owner/publisher queue has several consumers                                      | Queue remains inspectable inside its owner; dotted service exchanges retain all consumers and evidence.    |
| Two API operations share a component pair but perform reads and updates                 | Summary captures the broader purpose or separates it; detail retains exact operations.                     |
| Prose mentions a profile call, generated client exists, but no invocation is found      | Agent investigates use and preserves uncertainty instead of claiming a confirmed call.                     |
| Invoked source call exists but structured handler omits it                              | Agent repairs the typed relation with pinned evidence and validates the entry/target references.           |
| Two systems each connect to the core, but their mutual product/offer exchange is hidden | Agent audits business collaboration separately from graph connectivity and restores the supported purpose. |
| A connected group is detached from the main story                                       | Agent reviews the whole group and membership, not only zero-degree nodes.                                  |
| Scheduled export intentionally communicates outside the selected area                   | Agent explains the external purpose/scope rather than inventing an internal link or deleting the job.      |
| Partial scan finds no caller for a component                                            | Finding remains unresolved with a targeted next question, not “truly unused”.                              |
| Saved narrative references changed/removed evidence                                     | Agent reviews meaning and references; it does not merely update the basis or reviewed date.                |
| Expanded system grows beyond the viewport                                               | Whole boundary remains findable, controls legible, neighbours contextual; no detached supporting grid.     |

Use actual schema-compatible fixtures or pinned retained records when running these cases. Keep evaluation
outputs separate from production. Score the decisions, evidence and resulting diagrams, not exact wording.
Record which cases were executed and which remain a checklist. Retest only affected cases after a correction.

The skill's scope and progressive-disclosure structure follow OpenAI's
[Astra skill guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra).
Keep the entrypoint focused; add guidance only for demonstrated failures that change modelling decisions.

## Collapsed scope and label layering

Use a system that contributes to two independent activities and whose workspace component order differs
from the authored reading order. Its single collapsed card must lead with the intended primary activity
and retain the other work visibly. Expanding and collapsing must preserve both identities and exchanges.
Review intersecting routes at readable zoom: later-drawn lines must not strike through earlier labels,
and the keyboard description must remain available without duplicate focus targets.

## Maintenance and concise defaults

Use held-out areas rather than copying Commercial's shape. Supply existing records without a desired
answer and inspect the generated proposal and plot:

- Independent operational processes share sign-in providers and incidental business dependencies. The
  overview explains genuine operating exchanges while keeping the other work independent.
- A CMS source serves a brand site whose local component stages use an unrelated numbering scheme.
  Area-wide columns put the source before its consumer without reversing the actual request.
- A system's many secondary admin calls outweigh its one main overview entry. The collapsed anchor
  follows its selected responsibility and retains its other activity labels and component count.
- A new scan adds a second user of a private store. The agent revisits folding and every affected area,
  preserving record identities and source coverage rather than merely refreshing a fingerprint.
- A large expanded system follows a distant Fit map. Ordinary expansion restores readable text; the
  explicit fitted screenshot is labelled orientation, not proof that normal detail is legible.

Keep executed cases and outcomes in the run ledger. Shape validation and a skill validator establish
syntax only; inspect independent behavioural output and fix demonstrated decision failures.

For a multi-purpose system, inspect the first expanded viewport, not just whole-boundary geometry.
Primary query or purchase work should not open below a supporting preparation or saved-card band.
Check short-gutter labels against their own arrows and ensure All connections adds detail while retaining
useful concise summaries; an unexplained label under another line is a readability failure even if no boxes overlap.
