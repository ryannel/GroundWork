# Entry and operation listing budget

The production budget identified two oversized list routes. The entry list sent all 3,235 entries. The operation catalogue already paginated records but drew 3,529 repeated graph-gap messages on its first page.

The entry page now sends 30 entries with server-rendered previous and next links. The links retain domain, plan and before or after selection. Direct entry URLs still select the same full flow. A complete walk of the actual pinned Volvo input found all 3,235 entries exactly once in original order across 108 pages. The serialized first-page input is 7,757 bytes, down from 704,053.

Operation rows group identical gap kinds and exact messages with an occurrence count. All 155 records remain on their existing six pages. The first input is 15,844 bytes, down from 875,319. Every page's occurrence counts equal the complete canonical gap count. Full gap references, GraphQL documents and code citations remain unchanged in the index and on-demand inspector. Other reference kinds retain their existing gap rendering.

The measurement receipt records every page and the source hashes. These are serialized component inputs. The parent's production build and HTTP budget establish the final response sizes.

All 45 focused tests passed across six files. They cover exact pagination and identity order, selected plan links, direct entry selection, next-page rendering, repeated message counts, all original inspector gaps, and existing canvas and plan projections. Scoped lint, formatting and whitespace checks apply to the changed files.
