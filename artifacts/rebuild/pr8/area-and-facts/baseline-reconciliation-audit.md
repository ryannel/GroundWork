## Minimum reusable lineage checks

1. **Anchor frozen to actual migration source.** The PR4 fidelity ledger and reviewed exact differences explain the frozen→PR4 legacy reference (same supported authored/derived facts, explicit non-factual corrections). Validate frozen hash and exact PR7 authored source fingerprint/commit or small-workspace copied source fingerprint; enumerate actual data changes between them. The converter's own source digest and successful repeat prove stable migration inputs, not equivalence with an earlier baseline. Compare the relevant raw source branches to the legacy view where the latter added defaults, mixed in inferred records or had no path provenance.
2. **Normalise only named representations.** Use canonical aliases plus approved raw source locators for ambiguous namespace/step rows. Retain one row per occurrence (including the seven reviewed exact duplicate pairs). For each old current authored declaration, match by kind and explicit source identity, then enumerate old and new pointers/IDs and values/hashes. Preserve ordered steps, flow/stage/operation arrays and route narratives. Compare sets or maps only when contracts prove order irrelevant; use multisets when several sites have the same semantic key. Scope namespace rewrites to known reference fields; do not replace text or deduplicate unmatched occurrences.
3. **Prove backed sites and citations, then derive.** Old handler effects carry handler, on, from, to, target, kind, path, does, guards and async/looped/conditional context. Join original authored handler step by stable source selector/span and approved explicit step ID, then compare exact authored wording/conditions/guards and refs after aliases. Require a resolvable canonical site, its executable entry, matching native component endpoints (derive system endpoints from actual placement), and retained code/evidence locations. A code citation key is repository + commit + file + lines; prove symbol/label/note fields in canonical or exact source-note receipt. Where a backed legacy summary is split, prove its complete original backing site multiset survives; caller/producer/consumer/access query projections should agree with the site kind and direction. Unknown GraphQL clients and unbacked declarations need their exact accepted review + visible gap, never a fabricated caller. A declared narrative step still has its own meaning and is not substituted for an execution site.
4. **Prove authored catalogues and placements independently.** Check legacy entity shape→canonical schema mappings at the actual source pointers: app/topic/external/system namespace, moved provider, old contract endpoint/signature and errors, schema fields/defaults, screen/region/entry, messages/jobs, concept/term/target/flow/journey, owner/home/scan evidence. 112 human-reviewed classifications, 10 additional reviewed identities, exact Rockar merge, 76 unknown clients, 583 reviewed step IDs, exact uncited owner/edge dispositions and the original source/notes fingerprints are reusable receipts. Neither a kind-wide allowance nor a best-effort join is sufficient. Unmatched rows fail closed. The 14 restored area counts are an observed example where a blanket structural allowance would have hidden a loss.
5. **Plan before/after.** Prove old authored plan text + every operation/target to actual canonical overlays and provenance, not flattened legacy copied current. Existing three legacy context ledgers trace all 4,219 leaves and retain current concept references; exact consumer/deprecate/signature receipts cover subsequent reviewed changes. Validate actual ancestors, historical basis if present, and gap/proposed status per projected fact. Old loaded plan metadata is not proof of equivalent historical projection; observed no frozen bases in the three migration datasets.
6. **Presentation and deferred details.** Compare frozen route status, redirects, links/headings and full captured JSON separately; prove reachable native alias destinations, actual route/query selection and material fields. Record exact transport/header/order diffs only once the factual ledger passes. Browser evidence closure receipt verifies current+Care query parity, not every historical baseline observation. Native area receipt verifies every source band/caption/backing/anchor plus lossless full detail route. Keep old explorer material physically intact until its PR10 proof; a deliberate old URL redirect, an unavailable old asset and a retained capability are three different outcomes. Don't approve whole groups solely because route families have native names.

## Review exact differences from the completed candidate

The initial capture limitations above were addressed by native-only capture, checksummed fact shards, route-reader selected contexts and explicit capture replay. The factual evidence is divided by its actual claim: pinned code locations and handler sites; authored area and flow metadata; catalogue fields and legacy optional defaults; accepted plan overlays, progress and locks. The target and historical lock corrections have their own exact receipts.

Use each complete candidate's `comparison.json` as the row source. Assign a reason only to the exact tuple `[workspace, file, path, before, after]` after linking it to the corresponding proof. Keep these distinctions:

- Each new native fact shard is an exact addition backed by its checksum and manifest slot. Each removed legacy object branch needs the relevant source-to-native lineage; the format marker and manifest alone do not explain an old fact removal. A hash receipt for one family must not be used for another.
- A route's JSON shape can change once the corresponding backed data is traced. Add an allowance for its observed pointer and hashes, citing the route payload fields and verified preservation. A payload reduction needs a specific deferred detail lookup or exact stated retirement.
- Keep status, redirects and internal URLs separate from text and byte changes. Verify aliases and targets before allowing an old URL difference. A changed qualification, check state, warning or visible gap is not an ordering change.
- Apply known ordered-list retention and optional-default comparisons to the affected paths only. Where a view deliberately reorders a non-semantic collection, compare its identity/value multiset and record both orders. Do not sort or rewrite the frozen snapshot itself.
- Unknown or unproved rows remain unexplained. Re-run `--candidate` after writing the exact approved rows, so no changed response is accidentally accepted and no HTTP fetch is repeated for an allowance-only update.

In particular, do not generate allowances by broad file family, status class or wildcard path, or by trusting all differences in a proposed capture. If several exact rows share a reason, the receipt still enumerates the precise rows or the retained source facts that establish that reason.
