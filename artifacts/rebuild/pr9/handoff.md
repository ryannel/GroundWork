# Native scan and workspace skills

The pinned scanner writes a separate consolidated workspace candidate. It verifies the source tree
and retains cited spans under persisted evidence IDs. Contract fills require a unique route and
schema join or a pinned accepted review. Complete handler observations reconcile steps by verified
source coordinates inside their control-flow branches. Partial scans preserve the existing tree.
Ambiguities keep the prior step IDs and are reported. Cited analysis and its supporting records
are promoted only from a cache with matching repository, commit and file hashes.

The largest Volvo target is `volvo-cars/cdls-mono-volvocars`, with 772 of the 1,937 handlers.
Two scans used commit `75e70a353571b6ae78475636fe0e0056e5a7c2db`. Each verified the retained
2,651-shard source checkpoint and checked cited spans in 1,692 files. The first added 3,347
evidence IDs and refreshed 5,069 model records. The second wrote nothing. Git and SHA-256
compared all 1,599 output files, and the ordinary model index independently returned the same
392,185 IDs. The 108 unsupported references retain their historical citations. Of these, 106
refer to changed blobs and two refer to absent files.

The production-shaped Volvo inputs have no accepted semantic changes, no missing analysis
citations and no native route binding for this repository. The scan preserves those gaps. A
separate proof exercises the matcher on 166 real Volvo handler trees with deliberately changed
draft IDs. The focused tests exercise ambiguity, removal, lane names, causes, schedule conflicts,
retry behaviour, exact contract joins and promotion. The diagram audit used the consolidated
reader and projected all 14 areas. All PR9 data checks ran on temporary copies.

The scope is a refresh at the repository's recorded pin. Moving an existing repository to a
new pin or asserting complete handler coverage needs verified replacement evidence. The
historical checkpoint reports source extraction only. It does not establish deployed behaviour.
