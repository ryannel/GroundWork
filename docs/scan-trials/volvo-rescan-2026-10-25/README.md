# Volvo catalogue re-scan

All 108 catalogue repositories are authorised for the overnight re-scan. Source, interpretation and
question coverage are reviewed separately; an inventory or a valid source document is not full semantic
acceptance.

The [continuation record](../../../reports/volvo-rescan-2026-10-25/CONTINUE.md) identifies active workers,
checkpoints and remaining work. The [selected epoch](../../../reports/volvo-rescan-2026-10-25/control/selected-epoch.json)
is the authoritative pointer to current attempts. Earlier immutable captures and failure evidence remain
available, with selection receipts choosing successful replacements.

## Freshness

Remote default heads were observed for all 108 repositories. Forty-two differed from the previous
catalogue pins and were fetched into the existing source caches without switching working files or refs.
The current pinned trees contain 78,964 tracked entries. Actual source passes verify consumed bytes;
remote observation time and deployed currency remain separate. Four gitlink child sources are external
boundaries rather than silently included repositories.

## Reusable corrections

The initial captures exposed patterns absent from the bounded launch proofs. Corrections are retained in
shared code and native or adversarial regressions:

- Go leading comments, pointer writes, unnamed parameter types and assigned function literals.
- Empty Python and C# source, including distinct anchors for identical empty files in different paths.
- TypeScript lexical function references, object-property references and JSX arguments.
- Spring production source at either root or module level, type-use annotations and array writes.
- Java annotation arguments distinguished from execution assignments, with duplicate/conflict checks.
- Typed RestClient response extraction through `retrieve().body(Class)`.
- C# selected-program global imports, source shadowing, method route composition and action tokens.
- Unsupported native relationships retained as explicit gaps alongside the original AST, without
  inventing containment or weakening role validation.

Smaller source shards respect the existing artefact bound. An explicit source-size policy covers the
identified large C# test fixture; unsupported or quarantined analysis remains visible. Tests, generated
files, ancillary contracts and exclusions stay in the tracked-tree denominator.

Each selected capture records its immutable scanner directory and actual analysis digest. The first
repaired version is `20d1f0016e094f91da1394ce8f5ff9de2c66375c7ff1d21d556fc20893288033`; later TypeScript
selections use explicitly reviewed performance versions. The control adoption receipts retain the proofs
and their exact scopes. The fixed 19 depth checks, destructive mutations, cache/incremental checks and
native regressions validate tool changes. Per-repository results determine which questions can actually
be answered.

## Performance

Ordered source lookups replace repeated whole-index searches while preserving duplicate-span and owner
ordering. Three large real cached indexes produced byte-identical facts, with extraction time reduced
by factors of about 4.6–6.9 in those cases.

Checkpoint provenance previously re-read every scanner file for every planned scope at every checkpoint.
A batch now reads current analysis bytes once per checkpoint and preserves each scope’s own inputs. On
the actual 3,320-scope GraphQL plan, this stage fell from 17,962 ms to 77 ms with identical scope input
fingerprints. No fingerprint cache survives between checkpoints. These are stage measurements, not a
measured speedup for the whole corpus.

Source-size preflight uses pinned Git object headers before large reads. Generated action bundles need
positive, source-backed build recipes; unproved output remains selected. Large static fixtures need an
explicit canonical-data profile and bounded, complete content verification. Their samples do not become
API contracts or executable paths. Tracked entries and exclusions remain visible in either case.

## Outputs

Each repository retains its pinned inventory, checkpointed source shards, available framework and
program bindings, exact-input **Inferred** interpretations, explicit coverage review and source links.
The corpus catalogue provides a repository and file-to-shard index without loading every source graph.

Repositories with unrecognised frameworks, external/generated dependencies, oversized source programs or
missing runtime evidence retain partial obligations. In particular, source capture does not establish
complete JPA, Go RPC, wire, security, delivery or physical storage behaviour across every repository.
These boundaries must be carried into answers and any reader projection.

This pass captures and reviews evidence. Publication into the full workspace UI and production YAML
requires its own appropriate projections and acceptance; source-complete flags do not perform that
migration.

## Bounded publication

Repository v2 manifests retain trial identity, source artefact paths and extraction statistics, then link
to each committed completion file with its hash. Complete freshness observations stay in those files.
The `scan:adopt` command can publish fully verified native checkpoints without extracting them again;
it records the original analyser separately from the publisher and never overwrites the original capture.

Large logical scan graphs use `scan-framed/v1` storage with ordered, hashed JSON byte fragments. The
existing logical scan document and generation hash remain unchanged. Physical pages stay below 16 MiB;
source readers permit at most 256 MiB of logical data and explicit programme readers permit 512 MiB.
The caller chooses the limit. Every reconstructed graph still passes the source schema and role checks.

and [adversarial adoption review](../../../reports/volvo-rescan-2026-10-25/epoch-003/reviews/adoption-adversarial-java.json)
retain the concrete checks and remaining compatibility boundaries.
