# Customer Service source review

Twenty-one full pinned source/schema files were read independently. Actual controller forwarding preserves REST token/customer/request arguments and source response construction. Create/update/patch factories retain source differences; PATCH does not universally inherit validation groups' non-null requirements. Java25 identity record components were compared with original source; these are not aliases for the outer identity object.

saveAndPostProcess returns early for an equal customer, otherwise validates, saves Mongo, calls the separate Async postprocessor and returns the saved customer. Bulk save lacks the per-element validator. The postprocessor source body invokes customer/analytics publishers, saves audit, then invokes consent publisher; Async proxy activation/completion is unresolved, so these bodies are separately rooted rather than eagerly inlined into REST.

Direct analytics KafkaTemplate.send(message) retains its future and thenRun callback. Customer and consent sendSafely bodies are unavailable: null target/effect and an unresolved-library contract remain, with configured publication purpose separately recorded. The generic request_response classification here describes a source invocation with unresolved boundary/waiting, not an established remote request or acknowledgement. Customer metadata derives optional authenticated application ID; consent metadata/payload guards differ. No outbox, atomic save/send or broker completion is established.

forceArchive=false marks90days, true attempts immediate archive, contrary to source API prose. Archive upserts before deleting the live customer, catches per-item failures and can leave earlier effects; restore saves the live customer before deleting archive. The raw upsert binds created on insert, modified,customerId and original wholeCustomer; no global transaction is invented. Customer/archived_customers declared shapes and source indexes are distinct from observed applied schema.

Its supplied loaders, scheduled callbacks and joins remain distinct. Imported request/cache/serialization and callback scheduling are qualified.
