## Runtime identities and flows

The SoftOfferCreated census maps to **s2/subscription → s2/consumer → u3/runs/s2-consumer**; the appended Commercial dispatcher covers only the other eight typed branches. It does not introduce a second create consumer.

The Classification trace follows the actual API host, controller, local cache service and provider. It always attempts the Blob read at `global-product-data` / `/Classification.messagepack`. A successful read returns deserialised cached data; deserialisation failure does not trigger fallback. Any failed Blob read Result permits provider pagination. The provider uses limit 100 and offset accumulated data.Count, appends response.Data and repeats while Pagination.Total exceeds the count. It maps Id/Code into Classification, using the local IsType default false.

Successful provider retrieval and serialisation permit a whole-list MessagePack LZ4 Blob replacement. A successful upload Result is required before successful service data returns; this establishes a store-call acknowledgement, not cross-system atomicity. Controller source selects 200 for success, 404 for NotFoundError and otherwise 500 Problem; other imported error behaviour remains partial.
