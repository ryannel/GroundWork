# Policy admin independent source notes

Default Fx wiring uses in-memory PolicyRepository and CarRepository plus Azure BlobStorage. initializeDBCloseHook requires pgxpool.Pool but source default providers do not supply one; opts may change wiring, so declared routes/flows are conditional construction intent, not demonstrated deployment activation. Explicit route handlers are mostly empty; only PUT /v2/policies/ has update logic. Middleware has compression, no source auth wrapper. Swagger imported target is opaque.

UpdatePolicy decodes whole payload, converts command then calls imported CQRS Send; attempted200 does not establish completed handler/storage. CQRS source declares JSONMarshaler with StructName; publish/subscribe topic generator is commands.+name. The provider binds one GoChannel result as Publisher+Subscriber. EventBus/EventGroupProcessor helpers are not registered in default Fx list. Metadata sent_at is time.Now().String(); no Kafka broker or durable transport is established.

Handler reads pointer to policy already held in map, validates current+child builds, assigns Name/ConfigRules/CarLimitationRules through that pointer then calls Update, before Azure uploads. Error after these mutations does not revert in-memory state. Collected child builds are not persisted. Blob constructor creates container with Background context and ignores only ContainerAlreadyExists. ConfigRuleSet protobuf is marshalled, LZ4 writer.Write+Close are checked, then UploadBuffer uses rulesets/<ConfigRuleSet.Id>. Iteration can partially upload before later error. No global transaction/outbox.

getRequiredOptionsComponents sizes slice by IncludedOptions but fills GetRequiredOptions; source length mismatch/panic potential retained, not repaired in capture. In-memory car loader uses runtime.Caller-derived source directory and file car_specs_110.json, JSON tags model_year/spec_market/car_specification; each car_specification string is decoded again. The huge carSpecRaw constant is separate inert source data. Deployment file availability remains unresolved.

Standalone Python migration opens Mongo/Postgres at module top level. Only config_policy and components_policy migrations are invoked by main. DDL/helper functions for other collections are declarations, not active migration calls. Table creation commits before data rows, then a second commit; partial failure can leave schema/earlier writes. Source source-table names/uid fields differ from newer Filter pin; do not reconcile by name alone.
