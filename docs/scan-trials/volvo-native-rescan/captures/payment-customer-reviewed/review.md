## Blocking finding and source correction

Original prefix: `volvo/cds-paymentservice-customer/b0010537cdd5/`.

Affected examples were `contract/api-create.responses[200].body.sourceShape`, `contract/api-update-id.responses[200].body.sourceShape`, `op/controller-create.return.result` and `op/controller-update-id.return.result`. The sourceShape references pointed directly to CustomerResponseDto, and the terminal results to `value/controller-*.dto`. The same pattern affected the nine loop-authored business route responses. Whole-response cache hits already used a separate unknown BaseResponse shape, making fresh and cached results inconsistent.

`CustomerControllerImpl.java:96-102` and `169-175` declare `BaseResponse<CustomerResponseDto>` and return `SuccessResponse.ok(customerApiMapper.toDto(customer), this.getOperationId())`. The DTO and operation-ID result are **arguments** of that factory. Neither an unknown imported implementation nor partial-wrapper prose makes the inner DTO the returned outer object. Both version controllers also return BaseResponse via SuccessResponse.ok. `SwaggerUIControllerImpl.getSwaggerConfig` instead returns the raw imported SwaggerUIConfigResponse; it must not acquire a fabricated SuccessResponse wrapper.

Replacement prefix: `volvo/cds-paymentservice-customer/b0010537cdd5-r2/`. The selected closure now has `op/controller-*.wrap-response`, `value/controller-*.operation-id` and `value/controller-*.outer-response` for the eleven factory-returning routes. The nine business-route factory arguments remain their separate `value/controller-*.dto` values. Native flows preserve the DTO and operation-ID argument relationships. Contract body.sourceShape and terminal return.result select the outer shape/value. Unknown shared field names, inherited members and effective JSON are not guessed: outer shapes are empty partial declarations with the existing source/wire gap and unresolved factory resolution.

`value/controller-create.cached` and `value/controller-get-or-create.cached` now use the corresponding outer generic source shape. Cache-put flow starts from the fresh whole factory result, while cache-hit origins do not depend on constructing the current DTO or obtaining a new operation ID from the bypassed body. Two native source association claims preserve that distinction without claiming byte compatibility, effective advice ordering or cached contents.

The replacement also removes the stale `gap/save-sequence` assertion that the current schema cannot encode deletion. Deletion was already retained as an explicit conditional effect; this correction does not invent a per-iteration acknowledgement.
