# 08 Live Tasks And Reconciliation

## Goal

A user can work with live extracted tasks during a meeting, create or edit tasks manually, and have final task reconciliation preserve user-owned edits after rebuild.

## Why This Comes Now

Tasks introduce generated state that users can modify. They belong after live insights because reconciliation rules must distinguish draft machine output from user-owned task changes before final artifacts replace provisional ones.

## Included Scope

- Extract draft tasks from the live transcript during recording.
- Allow user task create, update, complete, and delete actions during the meeting.
- Track whether task fields are generated or user-owned.
- Reconcile final rebuilt tasks with live draft tasks and user edits after stop.
- Preserve user-created tasks and user-owned edits through finalization.

## Not Included

- Speaker-aware assignment suggestions.
- External task export or integration with third-party systems.
- Complex dependency graphs, recurring tasks, or subtasks.
- Audio playback and click-to-seek review flows.

## Acceptance

These criteria map to `tests/bets/meeting-recording/test_milestone_08_live_tasks_and_reconciliation.py`. Run via `./dev test bet meeting-recording`.

- [ ] Draft tasks appear while a live transcript is streaming.
- [ ] User can create, edit, complete, and delete tasks during recording.
- [ ] User-owned task fields are tracked separately from generated task fields.
- [ ] Final rebuild reconciles generated task candidates with live draft tasks.
- [ ] User-created tasks survive final reconciliation.
- [ ] User edits are not overwritten by final generated task output.
- [ ] Deleted user-owned tasks do not reappear from final reconciliation without an explicit conflict state.
