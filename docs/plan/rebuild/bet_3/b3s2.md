# Slice 2 — The hash-chained journal, and chain continuity in verify

Each journal line carries the hash of the previous line of its own session. The envelope moves to v2. A `chain` row walks each session and reports a break, a gap, or an unchained prefix.

This is done before the seal work so that every line written after it — including slice 3's seal lines — is chained. Doing it after would leave the seal lines outside the chain.

The chain is per session, not repo-global, because a repo-global chain would conflict on every merge. This repo's own ref already holds v1 lines from three bets, and the row has to name that unchained prefix rather than call it forged.
