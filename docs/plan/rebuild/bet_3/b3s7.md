# Slice 7 — The record row, the waiver counter, history shape, and the close scope

Four checks that all need bet boundaries, which only slices 1 and 3 create.

The record row judges declared records only. A row that invented obligations would become a friction-waived row, and the ledger already knows that class.

The waiver counter reads each waiver file's own git history rather than the journal alone. A shallow clone cannot see that history, so the row reports unrunnable and never counts zero.

After this slice the battery lock file is read from the HEAD blob. Bumping the version in the working tree and running verify before committing then reads as drift, which is the honest answer.
