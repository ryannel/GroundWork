# Slice 3 — Seals: one mechanism, four kinds

A seal is an annotated git tag naming the paths it covers, their blob hashes, and the battery version it was granted under. `seal verify` recomputes each hash at HEAD and names every path that moved.

It needs the plan files to point at, and the chain to record into, so it comes after slices 1 and 2.

Two limits are recorded rather than papered over. There is no signing key the agents cannot read, so unsigned seals are printed loudly and never count as human authority. And this host refuses tag pushes, so the tags are mirrored as blobs on a branch and rehydrated byte for byte.
