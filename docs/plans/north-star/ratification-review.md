# Ratification review — adversarial findings register

**What this is.** Seven blind, fresh-context reviewers read the full nine-file spec at commit `16c5ce4` (2026-08-06), each with one lens: internal consistency, reasoning flaws, operational failure modes, cost honesty, cold adoption, security and privacy, and life-cycle coverage. The driver ran its own blind pass before reading any of theirs, then triaged everything against the spec text. This file is the curated register; the full agent outputs live in the session transcripts.

**This file is evidence, not spec.** Nothing here changes the spec by existing. Each finding needs an owner disposition: amend, add to open items, scope out explicitly, or dismiss with a reason.

**Status tags.** `confirmed` — the driver verified the quotes and the logic against the text. `corroborated` — two or more independent reviewers converged on it blind. `plausible` — credible, not independently verified; owner judgment.

**Disposition (2026-08-06).** The owner directed a full fold-in, with one ruling that reshaped cluster A: tokens are the scarce resource, not dispatches — small dispatches are fine, total token consumption is the budget — and one addition: the framework must not bind to a single vendor (host portability, OpenAI-compatible hosts at minimum). Folded in four commits: `91aefb5` (A + F: token economics, honesty reframes), `ed15797` (B: contradictions), `bdd974b` (C + D: evidence-layer git reality, security floor), `1d25731` (E + G: operational life, the boundary, the host adapter contract). Security defaults, the flake/release/backward-move machinery, and the single-owner scope statement were driver calls under that mandate — flagged in chat as veto points.

## A. The economics are stale and unit-switched

- **A1. The dispatch arithmetic no longer holds.** (HIGH, corroborated ×3) loop.md and changes.md still claim "~20 frontier dispatches (from ~35)" — but the baseline was *total* dispatches measured, the target is *frontier-only* ideal, and the roles added at amendment time (blind test author, capsule writer, the standards cleanup pass, the design-seal adversary) are outside the count. Recounted like-for-like, a 3-milestone 8-slice complex bet costs ~50–60 total dispatches — more than today. The blind author, capsule writer, and cleanup pass also have no stated tier, violating index.md's own "leaving it off is an error."
- **A2. Measured-with-rework is compared to ideal-without-rework.** (HIGH, confirmed) The old 35–45 includes bounce rounds; the target 20 is a clean single pass — while the blind author is designed to *increase* bounce rounds, each priced elsewhere in the spec at up to 41% of a build.
- **A3. Complex slices became a serial 5–6 stage chain.** (MED, corroborated) Build → handoff/extraction → blind authoring → triage → battery → adversary → capsule, each stage fresh-context. Unattended throughput is bounded by slice latency, which roughly doubles. No elapsed-time budget exists anywhere; the journal doesn't record it.
- **A4. "Short brief" hides design-sized payloads.** (MED, confirmed) The blind author's input on the complex lane is the full sealed design walk, copied into ~8 dispatches per bet; the milestone-sum adversary must hold the assembled diff + design + tests + code and author new tests, inside a "three reads, no more" cap — the largest window in the system, presented as a reduction.
- **A5. The attention claim counts pauses, not decisions.** (MED, confirmed) "10–15 moments → the seals" compares decision counts to pause counts. A single bet-close sitting still holds ~15–25 discrete decisions (8 capsules, row-by-row board read, the drive, the teach-back, batched ratifications, doc approvals, merge go-ahead). The Map's own decision-budget instrument counts decisions; the headline should too.
- **A6. The frontier driver's own spend is invisible.** (LOW, confirmed) Spend-by-role covers dispatches; the driver is not a dispatch, yet assembles every brief, inspects every diff, triages every finding, and runs teach-backs. The likely priciest window is structurally absent from the "sorted column."
- **A7. The software replacing the prose is unpriced.** (MED, plausible) The word cut is measured to the thousand; the ~31 new build-list components (daemon, journal, board derivation, battery, UI-driver toolchains, update engine, sim rig) carry no maintenance-cost tripwire — at one-person scale, upkeep is the documented historic failure mode (384 commits).

## B. Internal contradictions (mostly amendment-sequencing damage)

- **B1. Tests-first vs the blind author.** (HIGH, confirmed) standards.md commands "Tests are written first and observed failing before the implementation exists"; proof.md now has complex-lane accepting suites written *after* handoff, and separately claims tests are "authored at decomposition, committed red, exactly as today." Three test-birth moments (decomposition headline proofs, blind post-handoff suites, auditor extensions) are never reconciled into one story. Followed literally, the sheet nullifies the blind author.
- **B2. Goal 11 has no mechanism.** (HIGH, confirmed) "Autonomy scales with verification… probe coverage of the touched area, not the task's label" — but the dial's stated inputs are owner choice, per-lane defaults (exactly a task label), and sensitive paths. doors.md asserts the computation; nothing defines it or wires it to the dial.
- **B3. The journal invariant contradicts dev mode.** (MED, confirmed) "No human or agent ever writes it" and the driver-written method-friction event appear in the same sentence's event list.
- **B4. The stopping rule's closed list has a sixth item outside it.** (MED, confirmed) "A genuine stop is only:" five items — then two bullets later, unaccepted-contract dependency is declared a genuine stop. A mechanical implementation of the list runs past it.
- **B5. "Open finding" means two incompatible things.** (MED, confirmed) "A slice cannot close over an open finding" vs "open deferred findings" that render on the known-gaps view precisely because slices closed past them. The finding state model (open blocks; deferred/dismissed don't) is implied, never stated.
- **B6. The module graph has two consumers, the retention test counts one.** (MED, confirmed) changes.md: "its one consumer is the ripple caller list," delete if unused. record.md still names it as the staleness check's indirect-drift reach. The retention test can delete the Record's own cited defense.
- **B7. The track record misattributes the twice-missed schema hole.** (MED, confirmed) index.md credits it to "magpie's own mechanical gate"; evidence.md and proof.md both place it in staycurrent (the loader/gate story behind ADR 0006). A factual error in the ratification headline.
- **B8. The no-daemon markdown fallback has no producer.** (MED, corroborated ×2) "The same pages exist as committed markdown" — but the six-writes deletion removed exactly the mechanism that committed pages, and rendering moved into the daemon. As specified, the fallback is raw ledgers, not pages.
- **B9. The read-only tower vs the Queue's writes.** (LOW, confirmed) Queue outcomes produce ledger writes and issue filings; the only named server is read-only, and no file says where those writes execute.

## C. Evidence-layer integrity (git reality)

- **C1. The journal is welded to a mutable DAG.** (HIGH, confirmed) Most events have no commit to ride (dial changes, triages, teach-backs, every red run on reworked-or-bounced slices — yet "a check with no journal lines is a check that never ran"). Parallel bets appending one file conflict at every merge; rebases duplicate lines; reverts delete them from an "append-only" record. The evidence layer for governance, sunset, and spend corrupts under normal git use. Fix direction: store outside the work DAG (notes/refs or owner-level log keyed by SHA + session).
- **C2. Merge topology is unpinned and teardown deletes the refs the views need.** (HIGH, corroborated ×2) One squash merge collapses a bet into a single trailer-less commit — the entire derivation erases and the bet renders as unlaned bypass. Seal tags point at commits that leave history when the branch is torn down. "Frozen forever" views are re-derived from refs teardown removes; no persistence mechanism is stated. Also the adoption angle: protected branches and required-PR-with-squash repos can't grant the git contract, and doors.md never names it as a precondition.
- **C3. Unattended runs have no failure containment.** (HIGH, confirmed) No retry ceiling or per-slice spend ceiling on a genuinely red row; no dead-run detection (quota exhaustion, crash, sleep — with worker changes deliberately unstaged); the push channel for genuine stops is "optional and deliberately undecided" while dial≥bet depends on it.
- **C4. The parallel design ignores its own lock-contention warning.** (MED, confirmed) evidence.md calls the 62% worktree index-lock failure "a warning the parallel design must engineer around" — no file engineers around it. Fix direction: one serialized git writer per repo.
- **C5. Tags aren't in the backup push; two machines diverge silently.** (MED, plausible) Branch pushes are automatic; tag pushes are never mentioned — seals granted on one machine are invisible to the other's Map, Queue, and `verify`. The tower reads local clones with no remote-delta indicator.
- **C6. Changed (not added) checks red live boards mid-flight.** (LOW, confirmed) Ratchet-arrival covers *added* checks only; a stricter existing check re-reds claimed-done proofs and stops every in-flight unattended run — "a release that turns projects red" reproduced by the spec's own mechanism.
- **C7. Hook failures are silent by design.** (LOW, confirmed) "Hooks do not [decay]" — they do (host updates, overwritten settings, fresh clones). Hook firings aren't journal events, so nothing ever notices surfacing has died; the system degrades to exactly the old invisible model.

## D. Security and privacy of the framework's own infrastructure

- **D1. The tower is an unauthenticated aggregation point.** (HIGH, confirmed) Every registered project's plans, ledgers, and in-flight state at one stable local address; the words authentication, binding, and origin appear nowhere in the spec. Any co-resident user or process — and, via browser tricks, remote pages — reads the whole portfolio. The open item covers lifecycle but omits auth entirely.
- **D2. Dev mode exfiltrates to a public repo.** (HIGH, corroborated ×3) Issues in the public framework repo carry journal lines, project paths, and session ids; no redaction step exists, and the auto-file opt-in publishes with no human look. "Maintainer" is a self-set local flag any adopter can flip.
- **D3. The debug journal commits secrets and pushes them.** (HIGH, confirmed) Debug widens lines to full check output — including secrets-scan output and real-infrastructure logs — committed into git history and immediately backup-pushed off-machine.
- **D4. The update engine is an unsigned supply chain into every repo's executable surfaces.** (HIGH, confirmed) Hooks (run at every session start) and CI stanzas auto-reconcile with no human review by design; no signing, provenance, or attestation anywhere; the package-hash check only confirms what was installed. One compromised release is silent code execution across every registered project and its CI.
- **D5. The unattended permission model is prose.** (MED, confirmed) "A *stated* permission model" — the spec's own doctrine is that prose loses; nothing enforces path allowlists, pins push remotes, scopes credentials, or bounds egress for multi-day runs, and the stopping rule fires only if the agent itself classifies the act as a boundary crossing.
- **D6. The evidence the battery produces is forgeable by the party it audits.** (MED, confirmed) Journal, ledgers, and seal tags are plain files/tags in a repo the agents fully write. "Append-only" and "the only way it moves" are conventions. Fix direction: hash-chained journal, signed seals, chain checked by `verify`.
- **D7. Brownfield day one executes the untrusted repo.** (MED, confirmed) Content is declared untrusted for *reading* while probes run the repo's own test/build commands the minute sockets map — before any seal or dependency audit ordering.
- **D8. The tower renders untrusted docs from one origin.** (MED, plausible) Agent-authored and brownfield-seeded markdown, no sanitization/CSP/isolation stated: one injected doc is stored XSS with read access to every project's pages.
- **D9. Registration is silent enrollment.** (LOW, confirmed) `init`/`update` register unconditionally; no per-project local-only/excluded visibility flag for NDA-bound work.

## E. The operational life of software (the spec's blind side)

- **E1. No break-glass path and no production-signal intake.** (HIGH, confirmed) The fastest lane still runs the full battery; an unrelated red row at 2am demands a sealed waiver ceremony. Nothing reads the observability the standards ship — no alert or user report ever reaches the Queue or Map; the only after-ship catcher is "the owner, in use."
- **E2. The system only knows forward — no revert, no abort.** (HIGH, corroborated ×3) Revert exists as a capsule *metric*, never a mechanism: after un-shipping, the permanent suite, manifest (`add-capability` has no remove), Map ("forever"), and Record all still assert the capability. Mid-flight withdrawal — which the record shows happening — has no terminal state: stalled-forever lines, undischargeable known-gaps entries, and branch deletion that destroys evidence. Fix direction: "reverted" and "withdrawn" as first-class states with a defined cascade.
- **E3. Flakes don't exist in the spec.** (HIGH, corroborated ×4) No retry, quarantine, or flake-rate concept anywhere, while the board treats red/green as truth, one red is a genuine stop at night, and the pairing rule just made the flakiest test class the headline row of every user-facing proof. Every flake routes through a sealed human waiver — the documented override-fatigue pathology by construction.
- **E4. Shipping stops at the merge.** (HIGH, confirmed) No product versioning, changelog, release channel, deploy environment, or staged rollout anywhere — and this spec never mentions feature flags at all (the ban lives in the old delivery contract), so there is no partial-exposure mechanism and no stated position on one. The front door proves the build, not the deployment; "shipped" for real users is outside every proof.
- **E5. Performance is named and then missing from its own list.** (MED, confirmed) standards.md announces "security, privacy, accessibility, and performance baselines" then enumerates rows for three of the four. The founding failure included a 5–10× slowdown going green; it still would.
- **E6. Dependency churn: detection with no response.** (MED, confirmed) A red audit row has no lane, owner, or cadence; a new CVE reds the battery for unrelated slices with no "world-changed" state distinct from "you broke it."
- **E7. Data operations are unproved.** (MED, confirmed) "Migration apply" is fresh-environment only: no down-migration proof, no duration class for hours-long backfills, no fixture-provenance rule for production-derived data (fixtures are policed for being too fake, never for being too real).
- **E8. Everything accretes forever; nothing bounds growth.** (MED, confirmed) Journal, archives, frozen views, and a delete-nothing suite — with the per-slice deletion test's cost scaling on suite size. At year three, battery latency quietly kills the patch lane's "checks-only cheap," and slow verification is the documented bypass trigger. No runtime budget, tiering, or segmentation exists.
- **E9. Succession is unaddressed.** (MED, plausible) Seals are identity-free tags on one laptop's registry; no handoff artifact, no second-seat model, no method-maintainer onboarding. Acceptable as explicit scope; absent as silence. (See G2.)

## F. Reasoning flaws in the evidence story

- **F1. A keep is justified from destroyed evidence.** (HIGH, confirmed) "Per-slice correctness review was never observed to rubber-stamp" — the raw review outputs were deleted for 21 of 23 bets and attribution was never filled; its miss rate is unknowable. The keep is right as a *prior*; the spec sells it as a measurement.
- **F2. "The split is evidence-based" is true for one third of the split.** (HIGH, confirmed) Only the honesty audit was measured. The edge-case lens (named same-slice catches, one build-killing) and coverage lens (repeated real findings) are demoted on the unmeasured claim that milestone-close "gives them more to bite on." Needs an honest label and a recurrence-triggered rollback clause.
- **F3. The escalation channel's evidence undermines itself.** (HIGH, confirmed) The contract exists because cheap models can't judge their own limits; a dozen "BLOCKING CONCERN: none" reports therefore can't be read as "works" — the false-negative rate is unknowable, and the tier policy tunes on that flattering signal. Needs an instrument for *missed* escalations (adversary tags findings the worker should have raised).
- **F4. The sunset regime can't see preventive success — and can't process its own calendar.** (HIGH, corroborated ×2) Zero firings is indistinguishable from perfect prevention (the spec says so itself about linters), yet fire counts are the deletion evidence; and dozens of dated items on six-month clocks vastly outrun one forcer-off experiment per model generation. As written it mass-rubber-stamps or mass-deletes working guards. Needs outcome-side metrics (defect-class recurrence) and tiered review classes.
- **F5. The blind author wears catches it couldn't have made.** (MED, confirmed) Every recorded catch of the green-but-wrong class came from reviewers reading code bodies — the one input the blind author is denied; internal-state corruption invisible at the interface passes it. Its marginal value over plan+adversary is a hypothesis: state it as one, gate lane-policy status on the blind-author-cheat sim, and declare its tier.
- **F6. Raising the dial destroys the evidence for not raising it.** (MED, confirmed) Escapes are found by human contact; higher rungs reduce contact per unit of work, so found-escape counts fall as autonomy rises — a one-way ratchet unless normalized by exposure (drives per delivered work).
- **F7. The patch lane re-opens the dominant recorded defect class.** (MED, confirmed) Tiny, gate-passing, build-killing changes — the record's own example — route to the review-free lane by the ties-lighter rule, and the lane audit (size and blast radius) scores that as correct. Needs a stronger router or sampled async review of landed patches.
- **F8. The Record's acceptance test is its training set.** (MED, confirmed) Checks tuned until the two repos the standard was derived from score as expected validates n=2 in-sample; the cold reader's "proven" rests on n=1 with unmeasured flag precision. Needs held-out calibration docs.
- **F9. The blind author's blindness cannot survive its own fix loop as specified.** (MED, corroborated) A suite must compile and run; harness layout, fixtures, and DI are outside the three-input list; compile errors and assertion diffs echo bodies. The sim's transcript-purity gate is sealed spec while the fix-loop visibility rules are an open item — the spec claims closed what the execution plan must square. Needs the laundering layer specified (driver runs the suite; failures return rephrased against design/plan; crossings journaled).
- **F10. The teach-back is exempt from the evidential economy.** (LOW, confirmed) The one major mechanism with no sunset class and no falsifiable check; its metric (decisions covered) can run green while teaching nothing.
- **F11. The per-case UI pairing overrides its own cost evidence.** (MED, confirmed) The record's evidenced remedy was milestone-headline drives; pairing scales the flakiest class to every user-facing case with the cost side unstated — repeat-waiver fatigue by construction. Consider scoping pairing to headline cases per milestone, or pricing it with a flake budget, and keeping UI twins out of per-slice mutation runs.

## G. The adoption boundary is real and undeclared

- **G1. Claude Code is a hard dependency the spec never names.** (HIGH, confirmed) Hooks, in-session subagents, session-id stamping, and transcripts-as-archive are load-bearing; no host requirement is stated and no degraded mode is defined for any other host.
- **G2. One human is the vision but never a scoped decision.** (HIGH, corroborated ×3) Every mechanism hard-codes exactly one owner (identity-free seals, one Queue, one registry, one judgment stream). The day a second person exists, acceptance becomes unattributable. Write the scope decision either way — and if single-owner stands, say what the handoff artifact is (E9).
- **G3. Libraries can't be driven.** (HIGH, confirmed) No topology for a package/SDK whose front door is an API consumed by code; the drive artifact is a hard mechanical gate with no defined meaning there — a library author must fake evidence or never seal. Needs a library topology (install-from-package, import, consumer-fixture round trip) and a drive definition.
- **G4. Multi-topology repos and monorepos have no answer.** (MED, confirmed) The manifest declares one profile; most real repos are several at once; "web" appears in an open item but not the canonical four; what "the project" is for a monorepo (registry entries, manifests, standards sheets) is undefined.
- **G5. No platform policy.** (MED, confirmed) "macOS first" exists only inside an open item; Linux/Windows adopters get the (broken — B8) fallback indefinitely with no statement of intent.
- **G6. Brownfield day one is self-contradictory.** (MED, confirmed) Deletion tests are on the "installs immediately, no sockets" list but require executing the mapped test socket; the day-one ratchet baseline predates the adoption-seal rules it would count. Ordering needs one honest pass.
- **G7. The battery's per-stack machinery is an undeclared extension point.** (LOW, confirmed) Marker filtering, run-log parsing, interface extraction exist as real code for six stacks; "every stack's test runner supports it" is asserted; who builds the adapter for stack seven is unstated.
